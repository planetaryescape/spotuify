## Local execution is an explicit repository setting

After registering a dedicated ARM macOS runner, set `SPOTUIFY_MACOS_ARM64_RUNNER` to a JSON label array, for example:

```json
["self-hosted", "macOS", "ARM64", "spotuify-builder"]
```

The native CI lane uses it only on trusted `main` execution. Pull requests remain hosted. The ARM release matrix can use the same setting; Intel and other platforms retain their existing routing. Validate runner availability before changing the variable: an unmatched label leaves jobs queued indefinitely.

## Rust and cache state belong to this runner

Reuse mxr's self-hosted Rust-home pattern. Scope Cargo/rustup homes beneath the runner tool cache and keep them separate from developer homes. Give spotuify CI its own sccache directory and port, and explicitly set `RUSTC_WRAPPER` to the installed sccache executable. Isolated Cargo homes do not inherit the developer’s Cargo configuration. Skip hosted cache cleanup actions on persistent local runners.

This addresses an observed mxr failure: cache cleanup removed the developer's rustup and crate sources, and shared sccache lifecycle interfered with developer builds. The exact source commits and paths are in [22](22-recovery-reuse-map.md).

Heavy local Cargo commands use `scripts/ci-cargo`, which requires `agent-work` on self-hosted runners and caps build/test workers at four. Hosted runners call Cargo directly. The queue owns compilation only; daemon launch, smoke, inspection and waits remain outside its build slot.
