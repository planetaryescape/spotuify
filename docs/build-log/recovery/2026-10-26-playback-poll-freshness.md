## The stale poll reached both clock and cache

The original focused test, `delayed_playback_poll_cannot_restore_previous_track_after_native_track_change`, failed before the fix: after the player advanced A→B while a poll for A was in flight, both the playback clock and durable cache reported A. The command was `cargo test -p spotuify-daemon --lib delayed_playback_poll_cannot_restore_previous_track_after_native_track_change --locked`; it exited 101. This exposed a gap in the earlier clock-only expectation.

An initial candidate, `84f34da78df4b73fd7d21c874f9923fd6a534ddc`, added poll ordering but failed a second deterministic case. Native event A waited for the transport lane; same-provider command B committed, then A overwrote B in clock and cache. That result changed the implementation boundary: native player state must reach the clock and user-visible event stream before session tracking and cache I/O can delay the relay.

## The current candidate applies native state before asynchronous work

Candidate `7f64f073e9479d7968b3c5a9ed4849e72a775ea8` applies playback and device activity synchronously in the relay, before awaiting session tracking or metadata (`crates/spotuify-daemon/src/state.rs#L5561-L5580`). `PlaybackClock::apply_player_event_with_activity` updates activity and the player-transition generation inside the clock write lock (`crates/spotuify-daemon/src/clock.rs#L222-L233`).

The relay then signals a coalescing native-cache worker. The worker rechecks provider ownership after it acquires the transport lane, snapshots current clock truth instead of persisting an old queued event, and preserves cached metadata when the current item is still a URI-only placeholder (`crates/spotuify-daemon/src/state.rs#L5482-L5498`, `crates/spotuify-daemon/src/state.rs#L5650-L5652`; `crates/spotuify-daemon/src/native_playback_cache.rs#L12-L65`). A `JoinSet` cancels the worker with the relay and the relay joins it on normal stream closure (`crates/spotuify-daemon/src/state.rs#L5486-L5498`, `crates/spotuify-daemon/src/state.rs#L5761-L5762`). Native event delivery does not wait on that SQLite work.

Web API polls capture both the command mutation sequence and native player-transition generation before the read (`crates/spotuify-sync/src/lib.rs#L72-L75`, `crates/spotuify-daemon/src/handler.rs#L4240-L4276`). Clock revision and device-activity callback checks happen under the clock write lock (`crates/spotuify-daemon/src/clock.rs#L409-L425`). Poll persistence also checks provider ownership and serializes with transport mutations; a current remote device remains reconcilable. The active native device rejects a different-URI poll whose Spotify state-change timestamp predates its local transition (`crates/spotuify-daemon/src/state.rs#L6065-L6085`). Spotify defines `timestamp` as when playback state last changed ([Get Playback State](https://developer.spotify.com/documentation/web-api/reference/get-information-about-the-users-current-playback)).

## Installed playback verification passes

The poll-focused suite passed 13 tests, including repeated stale polls, transition generations, the older and newer timestamp cases, and reconciliation of an older-timestamp phone snapshot. The same-provider command regression in `crates/spotuify-daemon/src/state.rs#L9164-L9280` verifies that queued native event A cannot overwrite command B in either clock or cache. That helper queues two native transitions while the lane is held, observes the second normal daemon playback event before release, then checks that later command C remains in clock and cache. An intentionally blocked version failed both assertions; the final version passed.

The first full workspace run on application commit `7f64f073` exited 101 after 393 daemon tests passed and one existing handoff test failed because it asserted that the playback clock remained stale while session tracking was locked. Test-only commit `743cd1cc` changes that fixture to wait for the actual playback-start event and for handoff state to reach the clock while the tracker remains locked. The updated focused fixture passed. The canonical workspace rerun on `743cd1cc` passed 2,025 tests, zero failed and one existing ignored across 82 groups. A subsequent CI Clippy run found an unused test helper; test-only commit `612411a5` scopes that helper to test builds and removes a stale intra-doc link. It changes no production logic. CI run `40388562733` passed all executed jobs on `612411a5`.

Independent maximum-effort review of application commit `7f64f073` passed with no blockers (DeepSeek V4 Pro, 30 requests at maximum effort, 689.41 seconds). The accepted review notes are bounded: cache I/O failure or cancellation can leave durable state behind the live clock; timestamp ordering is unavailable when the provider omits timestamps, equal timestamps do not order transitions, and clock skew can affect comparisons. A visualization observation was present on the base commit and is outside this fix.

The store's `fetched_at_ms DESC, id DESC` tie-break remains covered by the passing equal-timestamp regression: latest playback now selects the most recently inserted row when timestamps match (`crates/spotuify-store/src/lib.rs#L769-L781`).

If SQLite persistence fails, the native-cache worker logs the error while the live clock keeps player truth; the durable cache may remain stale. The installed check closes issue 007. Pending initial activation, external-device handoff, and S4 visual acceptance remain separate open checks.
